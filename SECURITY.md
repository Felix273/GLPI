# Security Policy

## Supported Versions

The latest version on the `develop` branch receives active development and security improvements.

Stable releases merged into the `main` branch receive security fixes as required.

---

## Reporting a Vulnerability

If you discover a security vulnerability, please do **not** open a public GitHub issue.

Instead:

1. Contact the project maintainers privately.
2. Provide a detailed description of the issue.
3. Include steps to reproduce the vulnerability.
4. Allow time for the issue to be investigated before public disclosure.

---

## Security Best Practices

- Keep GLPI updated.
- Keep PHP and database software up to date.
- Use HTTPS in production.
- Restrict administrative access.
- Use strong passwords and multi-factor authentication where available.
- Regularly back up the database and uploaded files.

---

Thank you for helping keep this project secure.
